# 坑位清单

## 架构图驱动决策

**坑**：先画"规划者→执行者→审查者"架构图，再找任务往里塞。角色图的美观与协作收益无关。
**判据**：唯一硬判据是同任务复测差值。图好看但复测没增益 = 纯成本。
**纪律**：默认不拆，加 Agent 是需要举证的决定；举证关答不上就先加工具/加 Skills/加审查环节。

## 跨基准比百分比

**坑**：拿论文里 +57%~80.8%（财务）和 -39%~70%（规划）互相抵消，得出"多 Agent 平均约等于单 Agent"。
**问题**：两个基准任务不同，百分比不可互比，更不能预报你的业务收益。
**纪律**：百分比只用于"说明方向可以相反"；你的收益只来自你自己的基线+复测。

## 45% 分界误读

**坑**：把论文里约 45% 的单 Agent 基线分界当阈值规则——"单 Agent 成功率低于 45% 就上多 Agent"。
**问题**：那是拟合出来的现象，不是可照搬的阈值；任务集不同分界位置完全不同。
**纪律**：任何"超过 X% 就该……"的规则，先问 X 是怎么拟合的、在你的任务上是否成立。

## 相似审查幻觉

**坑**：加一个审查 Agent，产出的答案和原答案相似 95%，就认为"审查过了"。
**问题**：相似答案不指出错误，只制造"已审查"的错觉；共享权重时还叠加自我确认循环（见 rsi-automation-playbook gotchas）。
**纪律**：审查必须引用证据（文件/行号/测试输出/数据出处）；无证据的"看起来没问题"= 无审查。

## 共享状态稀释

**坑**：拆多个 Agent 处理购物车/订单/用户偏好，各自上下文里状态版本不一致，交接时互相覆盖。
**问题**：共享实时状态在交接中被稀释，同时推高 token 和时延——Anthropic 电商场景因此选择单循环+Skills。
**纪律**：三问第 3 问不过就不拆；必须拆时，共享状态只走任务输入或落盘产物，禁止上下文默契。

## 交回"完成了"

**坑**：工作者说"搞定了"，编排者合成时才发现缺结论/缺测试结果/字段对不上。
**纪律**：契约五字段（问题/输入工具/交付物/停止条件/回传字段），缺一个退回；"完成了"不是交付物。

## 收益不稳定时不回头

**坑**：复测发现增益时好时坏，继续加角色、加机制去"调"。
**问题**：收益不稳定通常说明拆法或验收本身有问题，加机制只会放大交接成本。
**纪律**：收益不稳定 → 回查拆法（哪块其实不该拆）与验收（判定口径是否可复现），而不是继续加角色。
