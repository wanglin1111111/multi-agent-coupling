# 最小编排与交接契约

## 最小实现：外面只加一层

单 Agent 的 ReAct 是**内循环**（想→做→看结果→再想）。多智能体的最小改动是在外面加**编排层**，不是给内循环动刀：

```
编排层（新增）
  ├─ 为每个工作者建独立上下文
  ├─ 派发：写清问题、可用输入与工具、预期交付物、停止条件
  ├─ 调度：能独立的并行；有依赖的按顺序交接
  └─ 验收：查重、查冲突、退回修订、合格才合成

工作者们（各自原有的内循环，不改）
```

## 交接契约模板（子任务单五字段）

交回来的不能只是一句"完成了"。每个子任务单固定写：

```
问题定义        这个工作者要回答/交付什么（一句话）
可用输入与工具   明确到数据源/文件路径/工具名——不假设它知道别的
交付物格式       研究类: 结论 + 依据 + 未解决问题
                代码类: 改动清单 + 测试结果 + 已知失败
停止条件         什么情况允许交回 / 什么情况必须继续（防"做到 80% 就交"）
必须回传字段     契约点名的字段，缺一个 = 不合格退回
```

**共享状态纪律**：只能通过任务输入或持久化产物传递，**禁止靠上下文默契**——不能假设一个工作者知道另一个的上下文。要共享的东西，要么写进任务输入，要么落盘成文件路径传过去。

## 审查角色设计（验收环节）

编排者负责：查重（两个工作者结论矛盾）、查冲突（同时改同一产物）、退回修订。

需要纠错时，加的是**真能指出证据或测试失败的审查角色**：
- 合格审查：引用具体文件/行号/测试输出/数据出处说"这里错"
- 不合格审查：多生成一份相似答案——只稀释信号，不提高质量，比没有审查还危险（给了"已审查"的错觉）

流程：工作者交回 → 审查角色核对契约字段+证据 → 不合格退回（附具体理由）→ 合格才进合成。

## 反例清单

| 反例 | 问题 | 正解 |
|---|---|---|
| 规划者/执行者/审查者三角色标配 | 角色图美观 ≠ 有分工收益，先过三问 | 只加必要角色，最小化 |
| "完成了"式交回 | 编排者无从验收 | 契约五字段，缺字段退回 |
| 工作者 A "顺手"告诉 B 一些背景 | 上下文默契不可复制、不可审计 | 背景写进 B 的任务输入 |
| 审查者只说"看起来没问题" | 无证据审查 = 无审查 | 必须引用证据/测试/数据 |
| 改内循环去适配多 Agent | 破坏已验证的单 Agent 行为 | 内循环不动，编排在外 |
